## Methodology

- **Ground truth** is written inline in each dataset file as `[[TYPE|text]]`. Only personal data is labelled: names, emails, phones, postal addresses, IBANs, card numbers, government IDs and dates of birth. Organisations, standalone city/country names, business dates, times, amounts and ticket numbers are deliberately *not* labelled, so flagging them counts as a false positive (they are the ambiguity a reviewer has to resolve).
- **Matching** is overlap-based: a gold entity is found if any prediction overlaps it; a prediction is a true positive if it overlaps any gold entity. Precision = true-positive predictions / predictions; recall = found gold entities / gold entities.
- **PII chars covered** = share of labelled personal-data characters inside some predicted span (1 - this is the fraction that would leak if every prediction were approved and nothing else redacted).
- **Latency** = `durationMs` reported by the backend for detection only (Hybrid includes both detectors and the merge). It excludes HTTP and queueing time.
- Small, synthetic, English-only dataset: treat the numbers as a sanity check of the pipeline, not as a benchmark of real-world performance.
